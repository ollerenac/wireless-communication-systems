## Implementation Decisions

### Narrative Spine
- La leccion debe abrir con problemas de red: cobertura, throughput, interferencia, densidad de usuarios y mmWave/FR2.
- El orden narrativo debe ser: problema de red -> estrategia MIMO -> costo practico -> modelo matematico que justifica la decision.
- SVD, capacidad y DMT se conservan como herramientas de diagnostico y soporte, no como el centro de la sesion.

### Content Scope
- Preservar la intuicion de carriles/firma espacial y la aclaracion de que los streams comparten tiempo, frecuencia y banda.
- Preservar el modelo `\mathbf{y} = \mathbf{H}\mathbf{x} + \mathbf{n}` y explicar `\mathbf{H}` como diagnostico operativo: rank, condicionamiento, correlacion, normas de canal y CSI.
- Preservar comparaciones de detectores ZF/MMSE/ML/SIC y precodificadores MRT/ZF/RZF.
- Preservar TDD, pilotos, reciprocidad, pilot contamination y beamforming hibrido como problemas de red real.
- Reducir derivaciones largas de SVD, water-filling y DMT formal a cajas o secciones de soporte.

### Audience Fit
- El lector objetivo son estudiantes interesados en implementacion. Cada seccion debe responder "cuando uso esto" y "que costo pago".
- Los ejercicios deben convertirse en mini-casos de decision, no solo calculos de SVD/capacidad.
- El laboratorio debe presentarse como simulacion de decisiones de diseno, aunque el notebook siga siendo el mismo archivo por ahora.

### Verification
- `mkdocs build --strict` debe pasar.
- Usar `\mathbf` para vectores y matrices.
- Evitar LaTeX complejo en headings.
